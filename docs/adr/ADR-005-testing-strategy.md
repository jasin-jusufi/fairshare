# ADR-005: Testing strategy and TDD evidence

- **Status:** accepted
- **Date:** 2026-10-23

## Context

Tests are the most important guardrail for code generated by agents. The
AI-SDLC phase DEVELOP requires the order integration test → unit test →
implementation.

## Decision

Test pyramid with three levels:

| Level | Goal | Technique |
|---|---|---|
| Unit | Domain rules, use case logic | pytest, in-memory repositories, no frameworks |
| Integration | Acceptance criteria via HTTP + real DB | FastAPI `TestClient`, SQLite in-memory |
| E2E | Delivered artifact | `httpx` against the running Docker container; since 2026-10-27 also Playwright (Chromium) through the web UI |

TDD is visible in the Git history: per use case, first a commit
`test(uc-NNN): ... (red)`, then `feat(uc-NNN): ...` (green), then
`refactor`. Coverage target ≥ 90 % for `domain` and `application`; CI fails
below 85 % overall coverage.

## Consequences

- The acceptance criteria of every specification can be found 1:1 as integration tests.
- Red commits exist only on feature branches; `main` stays green.
